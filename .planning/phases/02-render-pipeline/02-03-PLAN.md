    **Gap 2 Fix — EffectComposer infrastructure proof:**

    The approach: Install `@react-three/postprocessing` and add a minimal EffectComposer that wraps the compositor's screen output. This proves the integration pattern for Phase 9 (per-era effects) without authoring any per-era passes yet.

    IMPORTANT NOTE on architecture: The current Compositor uses a manual `useFrame(priority=1)` render loop that renders to screen via `gl.setRenderTarget(null); gl.render(quadScene, orthoCamera)`. Integrating @react-three/postprocessing's EffectComposer with this manual render approach requires care:

    Option A (recommended — minimal change): Instead of using @react-three/postprocessing's React component tree approach (which expects to control the render loop itself), keep the manual render loop but add a SECOND render target pass for post-processing. The Compositor already renders the composite to screen; modify it to render the composite to a THIRD render target instead, then apply a post-processing pass (tone mapping + optional bloom) to that third RT and output to screen. This keeps full control in the manual useFrame loop and is the pattern Phase 9 will use for per-era effects.

    Option B: Use @react-three/postprocessing's `<EffectComposer>` component which takes over the final screen render. This conflicts with the manual render loop. Would require the Compositor to render its composite output into a scene that the EffectComposer then processes. More architectural rework.

    **Choose Option A** — it matches the existing manual render loop architecture and is what Phase 9 will build on. Implementation:

    1. Install: `npm install postprocessing @react-three/postprocessing`

    2. In `Compositor.tsx`, after the existing composite-to-screen step, add a post-processing pass:
       - Create a third WebGLRenderTarget (`rtComposite`) at canvas size
       - Change the composite render from `gl.setRenderTarget(null)` to `gl.setRenderTarget(rtComposite)`
       - After compositing, apply a simple tone-mapping/output pass that reads `rtComposite.texture` and renders to screen (`gl.setRenderTarget(null)`)
       - For the post-processing pass, use a simple ShaderMaterial that applies ACES tone mapping (which Three.js already does via Canvas gl settings, but this proves the "extra pass" infrastructure)
       - OR use `postprocessing` library's `EffectPass` + `ToneMappingEffect` programmatically (not as React components) within the existing useFrame loop. The `postprocessing` library (which `@react-three/postprocessing` wraps) has an imperative API:
         ```
         import { EffectComposer, RenderPass, EffectPass, ToneMappingEffect } from 'postprocessing';
         ```
       - Create the EffectComposer imperatively in a useMemo, add a RenderPass targeting the composite quad scene, and call `composer.render(delta)` instead of `gl.render(quadScene, orthoCamera)` for the final screen output
       - This proves that post-processing passes can be inserted into the render pipeline without disrupting the A/B compositor architecture

    3. Add a comment block in Compositor.tsx marking where Phase 9 will add per-era effects:

       // will be added here as additional EffectPass instances.
