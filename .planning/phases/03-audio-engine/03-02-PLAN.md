    Create src/audio/AudioEngine.ts as a class-based singleton (NOT a React component). This file is `"use client"`-safe but does not import React. All Tone.js construction happens in the `init()` method, never at module scope.

    Export `createAudioEngine()` factory function and `AudioEngine` class.

    AudioEngine class structure:
    ```
    class AudioEngine {
      private players: (Tone.Player | null)[] = []  // 13 slots, null if stem missing
      private gains: Tone.Gain[] = []                // 13 gain nodes
      private started: boolean = false
      private disposed: boolean = false

      async init(): Promise<void>
        - Create 13 Tone.Gain nodes, each connected toDestination()
        - For each AUDIO_ZONES entry, call loadStem() (see below)
        - Set up visibilitychange listener (AUDO-05)

      async start(): Promise<void>   (AUDO-01)
        - If already started, return
        - await Tone.start()
        - Start all non-null players (player.start())
        - Set started = true

      private async loadStem(zone: AudioZoneConfig, gain: Tone.Gain): Promise<Tone.Player | null>   (AUDO-06)
        - Create new Tone.Player({ loop: true })
        - try: await player.load(zone.stemUrl), player.connect(gain), return player
        - catch: console.warn with stem URL, player.dispose(), return null
        - Store result in players[zone.eraIndex]

      updateMix(currentEra: number, eraProgress: number): void
        - For each of 13 gains, compute target via computeGainForEra()
        - Call gain.gain.rampTo(target, 0.05) — AUDO-03 compliance
        - Only process gains within range [currentEra-1, currentEra+1] for efficiency (all others are already 0)

      private handleVisibility = (): void   (AUDO-05)
        - document.hidden → Tone.getContext().suspend()
        - !document.hidden && started → Tone.getContext().resume()
        - Do NOT call player.start() again on resume (pitfall #5 from research)

      dispose(): void
        - Remove visibilitychange listener
        - Dispose all players and gains
        - Set disposed = true
    }
    ```

    `createAudioEngine()` returns `new AudioEngine()` — does NOT call init() (caller does that in useEffect).

    CRITICAL anti-patterns to avoid (from research):
    - NEVER assign gain.gain.value directly — always rampTo
    - NEVER instantiate Tone objects outside init() — SSR crash
    - NEVER call player.start() on visibility resume — causes position jump
    - Players loop continuously once started; only gain controls audibility

    Create src/components/audio/AudioProvider.tsx:

    ```
    "use client";

    import { useEffect, useRef } from 'react';
    import { eraStore } from '@/store/eraStore';
    import type { AudioEngine } from '@/audio/AudioEngine';

    export default function AudioProvider() {
      const engineRef = useRef<AudioEngine | null>(null);

      useEffect(() => {
        let disposed = false;

        // Dynamic import to prevent SSR — Tone.js accesses window.AudioContext at import time
        import('@/audio/AudioEngine').then(async ({ createAudioEngine }) => {
          if (disposed) return;
          const engine = createAudioEngine();
          engineRef.current = engine;
          await engine.init();
        });

        // Subscribe to eraStore for scroll-reactive mixing
        const unsub = eraStore.subscribe((state) => {
          const engine = engineRef.current;
          if (!engine) return;

          // Gate: start audio on first scroll (AUDO-01)
          if (state.isScrollEnabled) {
            engine.start(); // no-ops after first call
          }

          // Update gain mix based on scroll position
          engine.updateMix(state.currentEra, state.eraProgress);
        });

        return () => {
          disposed = true;
          unsub();
          engineRef.current?.dispose();
        };
      }, []);

      return null; // renders nothing — purely behavioral
    }
    ```

    Key design decisions:
    - Dynamic import of AudioEngine module prevents Tone.js from being evaluated during SSR
    - eraStore.subscribe (not useFrame) drives audio updates — fires only on actual state changes, not every animation frame
    - engine.start() is called when isScrollEnabled becomes true (womb gate has completed, user can scroll) — this is the gesture gate for AUDO-01
    - AudioProvider is a permanent singleton — never unmounted (mirrors Phase 2 visibility-based scene management pattern)

    Update src/app/page.tsx:

    - AudioProvider has no visual output, order doesn't matter visually, but placing after Scene keeps behavioral components grouped
